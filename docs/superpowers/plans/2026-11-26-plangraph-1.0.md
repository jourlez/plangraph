# plangraph 1.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship plangraph 1.0: a deterministic project graph (requirements, decisions, plans, tickets, people, teams, repos, stack, history) that takes over an existing project or starts from one document, orchestrates the work, generates and refreshes documents, integrates read-only with Jira, GitHub and Confluence, and is used by Claude Code automatically at low token cost.

**Architecture:** Committed, byte-deterministic entity files and append-only batch files plus an uncommitted, rebuildable observation cache and SQLite index. Pure libraries under `lib/` (store2, history, ingest, flow, docs, digest) with thin commands under `src/commands/`, an extended MCP server, hooks and skills as the automatic callers. LLM judgment lives in skills; every fact a program can compute is code.

**Tech Stack:** TypeScript on Node 24.15+ with type stripping, `node:test`, `node:sqlite`, Python OR-Tools solver, `git` and `gh` CLIs through argv only.

**Spec:** `docs/superpowers/specs/2026-11-26-plangraph-1.0-design.md`. Evidence: `docs/research/2026-11-26/` (reports 01 to 09; report 06 has the file anchors). Independent audits of the first version of this plan: `docs/audit/plan-audit-A.md` and `docs/audit/plan-audit-B.md`; this revision answers every finding (last section).

## Global Constraints

- Runtime floor Node 24.15 (`src/floor.js`). No new runtime dependency without owner approval. Platforms: macOS and Linux. Windows is unsupported in 1.0 and the README says so.
- Output bounds (estimated tokens = ceil(chars / 4), `lib/render.ts:16`, calibrated in task 4): SessionStart card at most 250 (`CARD_BUDGET`, `lib/render.ts:14`); `hook-prompt` at most 200; `map` at most 500; `context` at most 400; `flow brief` at most 1,200; `graph` unchanged. Hook and plain stdout hard cap 10,000 characters. MCP upfront tool and instruction text under 3,500 characters.
- D24: no URL, host, email, token or account id in any committed file or generated document. Cache files are git-ignored, mode 0600, and the index file mode is 0600 too.
- Data class policy for generated documents: by default they contain ids, titles written by the plan and counts; person names, tracker free text and history-derived author data are excluded unless `docs.include` lists them. A D24 and data-class scan runs before every write.
- Determinism: committed files and generated documents have sorted order, LF endings, no absolute paths and no build timestamps. An event's `at` is an assertion, not a build time.
- Untrusted text (tracker, PR, commit, document, manifest scripts) is fenced and length-capped wherever printed. Repo commands copied into a brief (`test`, `build`) are labeled as data from the repository, never as instructions.
- plangraph stores no credential. Fetchers are read-only by construction (GET only, no write verbs in argv), serial, at most 100 items per page, honor `Retry-After`, use ETag where offered. A fetch target named in committed config runs only after the user trusts it locally (`trust`, task 20); `gh` uses the user's own token, so the docs say "read-only requests", not "read-only scopes".
- LLM-written text is never a committed fact. LLM digests and narrative blocks are out of scope for 1.0.
- Every new exported function has a production caller (command, hook, tool or skill); `test/callers.test.ts` (task 33) enforces it.
- Storage (spec section 4.0): one `.pg` entity file per node under `nodes/<kind>/<h2>/`, `.jsonl` batch files for events and runs, immutable schedule version files. Wherever a later task says `<kind>.jsonl` for a committed kind, read it as that kind's entity directory through the `PlanStore` interface (task 6) and the `links` and `xrefs` lines of the source node. No merge driver and no `.gitattributes` merge entries exist after task 11; `plangraph check` is the integrity guard and `plangraph resolve` repairs mechanical conflicts.
- Plan anchors (file:line, signatures) come from an audit of 0.5.0 and are hints: verify each against the code before using it; if it differs, follow the code and say so in the commit body.
- Test runs per task: only the tests the task names (`node --test <files>`), plus `node scripts/typecheck.ts`. The full gate (`npm run bulletproof:check`, `npm run knip`, `npm run mutate`, baseline compare) runs once per wave. Wall-clock performance bounds live only in the `CI_SLOW=1` group (never in default unit runs) and are set at 10x the measured median. Never run `npm ci` or `lefthook install` in a worktree; symlink `node_modules`.
- Commits: plain imperative subject, no `Co-Authored-By`, no AI attribution, no private names, emails or home paths.
- Controller-owned (implementers never edit): `scripts/mutate.ts` pins, `scripts/mutate/*.json`, `test/golden/mutation-kills/*.json`, `scripts/baseline.ts` probes, `KNOWN_ISSUES.md` (empty at a release), `PENDING_DECISIONS.md`, `CHANGELOG.md` release sections, version pins. Tasks that invalidate pins (5, 9, 10, 11) schedule the controller's pin edit as their last step.
- Registry rule: one `writes` and one `guard` per command name (`src/registry.ts`). Every writer is its own command: `flow-claim`, `flow-progress`, `flow-done`, `flow-link`, `identity-map`, `docs-build`, `githooks-install`, `trust`, `resolve`, `fmt`, `compact`, `sync-fetch`, `uninstall`, `ingest` (all subcommands write), `repo` (writer). Read-only commands never share a name with a writer.

## Review Focus

Most likely to bite a person; each has a test in the task named.

1. A shallow clone, or a blobless clone where `--numstat` would fetch every blob: `ingest git` refuses a shallow clone with exit 2 and one line, warns on a blobless clone, and writes nothing partial (task 16).
2. A rebased or force-pushed branch makes the stored cursor SHA unreachable: the ingest rebuilds and keeps no stale facts (task 16).
3. Tracker, PR, commit or document text containing instructions never reaches `map`, `context`, `flow brief`, `hook-prompt`, a generated document or an MCP result unfenced (tasks 17, 22, 24, 27, 28, 29).
4. Merge conflicts and hand edits: a file with conflict markers or a bad line never takes the tool down; it is skipped with `CONFLICT_MARKERS` or `BAD_LINE`, reported in one line, and `resolve` fixes the mechanical cases (tasks 8, 9).
5. A hook runs with no git repo, no plan directory, no index, a stale cache, no network, or an exceeded budget: it prints nothing, exits 0 and never blocks (task 29).
6. Two ids that differ only in case, and two agents writing in one clone: case-insensitive file systems and the store lock never lose or merge data silently (tasks 8, 21, 33).

### Task 8: Storage primitives (`lib/store2`)

Spec 4.0 is the design. This task adds the new storage as a library with tests; commands do not use it until task 10.

**Files:** Create `lib/store2/layout.ts`, `lib/store2/pg.ts`, `lib/store2/nodes.ts`, `lib/store2/batches.ts`, `lib/store2/txn.ts`, `lib/store2/check.ts`, `lib/store2/resolve.ts`, `src/commands/fmt.ts`, `src/commands/resolve.ts`, `src/commands/compact.ts`, tests `test/store2-layout.test.ts`, `test/store2-pg.test.ts`, `test/store2-nodes.test.ts`, `test/store2-batches.test.ts`, `test/store2-txn.test.ts`, `test/store2-check.test.ts`, `test/store2-merge.test.ts`, `test/store2-resolve.test.ts`. Modify `src/commands/index.ts` (`fmt`, `resolve`, `compact` writers; `check` runs the store validator).

**Interfaces:**
- Layout: `nodePath(root, kind, id): string` is `nodes/<kind>/<h2>/<slug>~<h8>.pg` where `h8` = first 8 hex of sha256(exact id), `h2` = its first two characters, `slug` = the id lower-cased with every character outside `[a-z0-9._-]` replaced by `_`, at most 60 characters. File names are case-insensitive-safe because the hash differs for ids that differ only in case. `newId(kind, seed: string): string` = kind prefix plus 6 hex of sha256(seed) (extended by 2 hex on collision); the seed is creation input (a requirement's source anchor plus its first 40 characters at creation, a decision's source path), never later-edited content.
- `.pg` text format: line 1 `id <json string>`; then one line per field `<name> <json value>`, sorted by name; a collection field (`links`, `xrefs`, `acceptance`, set-valued fields such as `members`, `owns`, `affects`) repeats its name once per element with the elements sorted by their canonical JSON; no commas, braces or blank lines at line ends; LF; trailing newline; each line at most 8 KiB; unknown fields are kept and sorted with the rest. `Node = { id: string; [field: string]: unknown }` where collection fields are arrays. Reserved fields: `schema_version`, `src`, `fp`, `derivation`, `valid_to`, `superseded_by`, `links` (`{rel, to, attrs?, until?}`), `xrefs` (`{sys, xid, src?, seen?, note?}`).
- API: `formatPg(n: Node): string`, `parsePg(text: string, path: string): ParseResult` returning `{ node } | { problem: 'CONFLICT_MARKERS' | 'BAD_LINE' | 'ID_MISMATCH'; line: number }` (never throws on content), `readNodes(root, kind): { nodes: Node[]; problems: Problem[] }`, `writeNode(root, kind, n): 'created' | 'changed' | 'same'`, `deleteNode(root, kind, id): void`, `renameNode(root, kind, from, to, opts?: { keepAlias?: boolean }): void` (moves the file, rewrites `links` and `xrefs` that pointed to it in other nodes, leaves `alias_of` on the old id when `keepAlias`), `eraseNode(root, kind, id): ErasePlan` (prints every file, event line and link naming the id; does not rewrite git history).
- Batches: events live in `events/<yyyy-mm>/<actor>.<bh8>.<dd>.jsonl` where `bh8` = first 8 hex of sha256(branch name at write time) and `dd` the day; `appendEvent(root, actor, e): Event` assigns `at` = max(wall clock to the second, latest `at` seen in `readEvents`) and `seq` = a counter that increases within one `at` for the file, so a clone with a fast clock cannot silently outrank everyone else; `readEvents(root): Event[]` sorted by `(at, seq, actor, bh8)` and de-duplicated by `(task, to, by, at, seq)`. Runs: `writeRun(root, kind, rows)` writes `runs/<kind>/<yyyy-mm>/<h8>.jsonl` where `h8` is the content hash (identical runs are one file). Schedules: `schedules/<version>.jsonl` with `version = v<n>-<h8 of content>`; `schedules/CURRENT` holds one version name; `setCurrent(root, version)`. `compact(root, opts)` merges sealed months into one content-hashed file per month and kind and refuses unless `CI=true` or `--ci` is passed (compaction runs only on the default branch in CI so two clones cannot race); events later than a compacted month land in a fresh file.
- Transactions: `withTxn(root, fn: (tx: Txn) => void): void` stages writes under `.plangraph/.txn/<id>/`, journals them, then renames into place; an interrupted transaction is rolled forward or back on the next call to any command; takes the existing store lock so two agents in one clone serialize.
- Validator: `checkStore(root): StoreViolation[]` with codes `ID_MISMATCH` (name hash differs from the id inside), `DUPLICATE_ID`, `CASE_COLLISION` (two names equal ignoring case), `NOT_CANONICAL`, `DANGLING_LINK`, `BAD_SCHEMA`, `CONFLICT_MARKERS`, `BAD_LINE`, `UNSORTED_BATCH`, `SYMLINK`, `OVERSIZE` (over 256 KiB), `MISSING_CURRENT`; each carries `path`, `line`, a one-line fix. Readers skip a problem file, never throw, and the card prints one line `store: N problem files (run plangraph check)`.
- Commands: `fmt` rewrites every `NOT_CANONICAL` file; `resolve` finds files with conflict markers and, when every conflicting hunk consists only of lines of collection fields, resolves by union and sorts; a hunk touching a scalar field is left in place and reported with file and field; `check` exits 1 on any error-class violation.
