# Graph Model v2 Implementation Plan (0.4.0 expand, 0.5.0 migrate)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make people, sprints, epics, plan tasks and capacity first-class graph data with one blocker definition and a `brain graph` command, without changing any existing command's output and without storing any fact twice.

**Architecture:** Expand in 0.4.0 (new keyed node files, and a `links.jsonl` set for hand-authored links that have no v1 source, read when present; every relation view derived from v1 data; the format guard reads and writes a newer directory whose `min_reader` it meets (Task 2A); `format_version` and `min_reader` stay 1), migrate in 0.5.0 (`brain migrate --write` appends the missing node rows and keeps existing ones, writes no `links.jsonl` and changes no v1 file; `format_version` 2, `min_reader` 1, readable and writable by 0.4.0 and later, refused by 0.3.0). All six relations (`needs`, `assigned_to`, `scheduled_in`, `belongs_to`, `implements`, `held_by`) are derived from their v1 homes (`edges.jsonl`, `schedule.jsonl`, `tickets.epic`, `refs.plans`, `open-items.jsonl`; five in the index view `g_links`, `held_by` in TypeScript from the open-items file) and are never stored in `links.jsonl`. The contract step is a later major version. The section "Design on a page" below is binding: every task matches it, and a task that needs to differ changes that section first.

**Tech Stack:** as the 0.3.0 tree (TypeScript 7.0.2, Node 24.15+ (0.3.0 Task 11, decision D20), `node:sqlite`, `node:test`, Biome formatted, full strict flags). Zero runtime dependencies.

**Spec:** `docs/superpowers/specs/2026-11-23-graph-model-v2-design.md`, with the decisions of `docs/superpowers/specs/2026-11-24-zero-gaps-design.md` sections 14 and 16 (D7, D10, D18).

**Status:** written against the planned 0.3.0 outcome. Before Task 1 starts, the controller re-checks every file and interface named here against the released 0.3.0 tree and records differences in the ledger (this plan was written before 0.3.0 existed).

## Design on a page

Every task matches this section; names here are the names in the code.

**Files** (all in the brain directory; v1 files unchanged in shape):

| File | Kind | Key | Fields | Written by |
|---|---|---|---|---|
| `people.jsonl` | node | `id` | `id`, `name`, `active` | hand; 0.5.0 migration appends missing ids |
| `sprints.jsonl` | node | `n` | `n`, `name`, `start?`, `end?` (`YYYY-MM-DD`, `start <= end`), `state` | hand; migration appends |
| `epics.jsonl` | node | `id` | `id`, `name` | hand; migration appends |
| `plantasks.jsonl` | node | `id` (= `<plan>#<task>`) | `id`, `plan`, `task` (no `fp`: it stays in `refs.plans[].fp`) | hand; migration appends |
| `capacity.jsonl` | node | `person` + `sprint` | `person`, `sprint`, `sp` | hand only |
| `links.jsonl` | set | whole record | `from`, `from_type`, `rel`, `to`, `to_type`, `attrs?` | hand only; no command or migration writes it |

Node files merge by key (field-level three-way merge, `lib/merge.ts`); `links.jsonl` merges as a set. One reader, `parseGraphFile(name, text)` in `lib/graph/files.ts`, validates every graph file for `readGraphFiles`, `brain build`, `brain check`, `brain doctor` and the migration.

**Node types and endpoints:** `NodeType = 'ticket' | 'person' | 'sprint' | 'epic' | 'plantask' | 'openitem'`. A node is the pair `(id, type)`; ids are unique per type only (`sp:<slug>` is a ticket and an epic). Sprint ids are `S<n>`; plan tasks `<plan>#<task>` (not parsed: a `plantasks.jsonl` row's `id` must equal `plan + '#' + task`, and a plan path or task may hold `#`); open items `<key>|<kind>` (exactly one `|`). Implicit nodes: people from non-empty schedule owners, sprints from integer schedule sprints, epics from non-empty `tickets.epic`, plan tasks from the `refs.plans` entries that are objects with a string `plan` and a string `task` (other entries give no node; `refs.plans` entries are unchecked, `lib/stale.ts:17-19`); an implicit node is never a violation.

**Relations:** `DERIVED_RELATIONS` (never stored; `V1_HOME` names the file): `needs` Ticket to Ticket (`edges.jsonl`), `assigned_to` Ticket to Person and `scheduled_in` Ticket to Sprint (`schedule.jsonl`, per version), `belongs_to` Ticket to Epic (`tickets.jsonl` `epic`), `implements` PlanTask to Ticket (`refs.jsonl` `plans`), `held_by` Ticket to OpenItem (`open-items.jsonl`). `RELATIONS` (hand-authored, D18): `relates_to`, any type to any type, informational, read by no blocker, capacity, solver or verify logic.

**Index** (`src/db.ts`): tables `person`, `sprint`, `epic`, `plantask`, `capacity`, `link` join `DEFS` (so `SOURCE_FILES` and the content digest); `open-items.jsonl` stays out of the index. `sourceFingerprint` hashes a graph file only when it is present (a missing graph file adds no bytes), so a v1-only directory keeps its 0.3.0 fingerprint and the `--json` envelope's `fresh.fp` (`src/context.ts:115`) does not change. The card hash follows the same rule: the six graph files are listed in a new frozen `GRAPH_SRC_FILES` (`src/commands/shared.ts`), and `cardLineText` (`src/commands/queries.ts:335-339`, which hashes a missing `SRC_FILES` entry as `<name>\0 0\0\0`) hashes each of them only when `presentDataFile` is true; `SRC_FILES` itself is unchanged, so `firstUseLine` (`src/commands/queries.ts:357`) keeps its 0.3.0 checks and a v1-only directory keeps its card digest (measured on a scratch copy of `89193c9` with the baseline plan fixture: card line `@1209969b` before and after the change). The content digest of an index with exactly the 0.3.0 schema is computed over the 0.3.0 table list. Every column name in SQL built from `TABLES` (DDL, insert column list, digest `ORDER BY` and `json_array`) and in the Python mirror is double-quoted, because the `link` columns `from` and `to` are SQL keywords. Views `g_nodes(id, type)` and `g_links(src, src_type, rel, dst, dst_type, version, kind)` hold every node type except `openitem` and every relation except `held_by`. `schemaOk` accepts exactly these tables and these two views with byte-equal `sql`. The Python solver `bin/brain-solve` is the second consumer of the index schema: its `INDEX_TABLES`, `schema_ok` and `content_digest` mirror `src/db.ts` (the same tables in `TABLES` order, the same two views with byte-equal `sql`, no other view or trigger), changed in Task 2 together with `test/brain-solve-input.test.ts`. An index with exactly the 0.3.0 schema is an older schema: `openIndex` verifies its content digest over the 0.3.0 table list and then sets `stale = true` and `PRAGMA query_only` whatever its fingerprint (a v1-only directory has the same fingerprint under both versions, so the fingerprint alone would call it fresh, `src/db.ts:388-390`); v1-only commands answer with the STALE warning; commands that read `g_*` (`ticket`, `neighbors`, `chain`, `person`, `sprint`, `graph`) exit 2 with `STALE` and `try: brain build`; every index writer (`openIndex` with `readOnly: false`: `whatif --write`, `schedule-load`, the export stamp `stampFingerprint`) refuses it with `STALE` and `try: brain build` before any write (without the refusal `stampContent` over the new table list fails with `no such table: person`, measured).

**Library:** `lib/graph/files.ts` (schemas, `parseGraphFile`, `readGraphFiles`, the constants), `lib/graph/views.ts` (DDL, `reach`, `graphReader`, and `BlockerSource`, declared here and re-exported by `lib/graph/blockers.ts`), `lib/graph/integrity.ts` (`integrity`), `lib/graph/blockers.ts` (`modelSource`, `blockersOf`, `BlockerReason`), `lib/capacity.ts` (`capacityFor`). `reach` is breadth-first with a visited set on `(id, type)`, first path per node, `depth` 1 to `GRAPH_MAX_DEPTH = 20` (named apart from the existing `MAX_DEPTH = 50` of `neighbors`, `src/commands/queries.ts:70`), and follows versioned rows (`assigned_to`, `scheduled_in`) of one schedule version only, `version = 'current'` by default. `ticket`, `person` and `sprint` run on `reach`; `neighbors` (depth 0 to 50, every edge kind) and `chain` (unbounded longest-path DP with its cycle error, ignored kinds left out) keep their own algorithms over the `needs` rows of `g_links`, because a depth-capped shortest-path search cannot give their answers. `held_by` covers open register items only; the `needs` rows of `g_links` hold every edge kind, with the edge's `kind` in the `kind` column (NULL for every other relation and for an edge row without a kind, exactly as the `edge` table holds it), and each consumer filters `ignore_link_kinds` on that column as today (`chain`, `src/commands/queries.ts:90`, `check`, `:199`, and `buildModel`, `lib/model.ts:72-75`, skip by kind, so a view without the column could not serve them; a NULL kind is never skipped, measured on `89193c9`: an edge without `kind` blocks under `ignore_link_kinds: ["plan_need"]`). `GraphReader` (index) extends `BlockerSource` with `node` and `reach`, and adds `held_by` from `readItems`. `modelSource(model, items)` is the `BlockerSource` for code that holds a `Model` (`lib/ready.ts`).

**Checks and codes** (one owner each): `parseGraphFile` throws the data errors (exit 2) `LINK_UNKNOWN_REL`, `LINK_DERIVED_REL` (names `V1_HOME`), `DUPLICATE_NODE` and field-shape errors; `integrity()` returns `LINK_MISSING_NODE` (a `links.jsonl` endpoint that is neither a row nor an implicit node; an `openitem` endpoint exists when a register row of `open-items.jsonl` has that `key|kind`, any status) and the warning `UNDATED_SPRINT` (some `sprints.jsonl` rows dated, others not). `brain doctor` catches `DUPLICATE_NODE` and prints the fix line instead of exiting; it prints the integrity count and `brain check`, the command that lists them, only when the count is above 0. Exit codes: `brain build` prints each violation on stderr (`error:` for `LINK_MISSING_NODE`, `warning:` for `UNDATED_SPRINT`) and still builds (exit 0); `brain check` prints each violation and exits 1 on a `LINK_MISSING_NODE` (as it exits 1 on any rule violation today), never on a warning alone; `brain doctor` keeps its exit code. No `LINK_WRONG_TYPE`, no cycle code, no double-placement code.

**Blockers:** `blockersOf(key, src, { statuses, closed, ignoreKinds })` applies, in order: done (stop), verdict, finding, held_by, needs (a producer with no ticket row is skipped); each reason carries what `brain ready` prints (verdict string; finding kind and text; item kind, owner and text; producer key, status and impl flag). `readiness` delegates to it and adds the producer's placement from `model.sched`. `brain blockers` is not a blocker report: it lists the stored verdicts other than READY, closed tickets included (`src/commands/queries.ts:147-148`), keeps its SQL over the `ticket` table and does not call `blockersOf`. `modelSource` builds per-key maps (findings, items, edges with their kind) once per `(model, items)` pair: `readySet` and `readyScope` build one source and pass it to every `readiness` call through a new optional `ReadyOpts.source` (a source built inside each `readiness` call would make `readySet` quadratic in the number of tickets); a producer's `kind` is passed through unchanged, `null` when the edge has none, never defaulted to `plan_need` (a defaulted kind would skip such an edge under `ignore_link_kinds: ["plan_need"]`, while `buildModel` keeps it).

**Commands:** new `brain graph KEY [--rel R[,R]] [--depth N] [--reverse] [--type T]` (global `--json`, `-v`); ids fenced except ticket keys (`oneLine`); output capped by the existing limits; it follows the `current` schedule version only. `whatif` and `--relieve` use `capacityFor` (`min(row, capOf)`); `verify`, `check` and the solver keep `capOf`. `forecast` and `report` use sprint dates only when every sprint in the window is dated.

**Guards:** `formatGuard` and `firstUseLine` call `checkFormat` in `read` mode: a directory with `min_reader <= FORMAT_VERSION` is read and written, a higher `min_reader` is `TOO_NEW`. Guards on `89193c9`: `strict` = `export`, `refs-update`, `learn`, `report`, and `open-items` with `--write`, `--close`, `--reopen` or `--register`; `none` = `init`, `migrate`, `doctor`, `explain`, `bundle`, `integrations`, `jira-pull`, `jira-text`, `jira-import`, and `card --if-present` (the hook; its first-use nudge does its own read-mode check); every other command `soft` (including `build` and `schedule-load`, which write only the index). `brain graph` is `soft`.

**Migration 1 to 2** (0.5.0, `min_reader` 1): appends missing node rows (owners and sprints of every schedule version, non-empty epics, every `refs.plans` entry), keeps every existing row byte for byte, aborts on `DUPLICATE_NODE` before the first write, writes no `links.jsonl`, changes no v1 file, writes a node file only when it appends; idempotent and crash-safe through the existing framework. 0.3.0 refuses the result; 0.4.0 reads and writes it. `brain init` writes `min_reader` = the `min_reader` of the newest migration (1), not `FORMAT_VERSION` (`src/commands/plan.ts:236` on `89193c9` writes `min_reader: FORMAT_VERSION`, which would give 0.5.0's new directories `{2,2}`, refused by 0.4.0).

**Baseline probes:** new `integrity-*` (Task 3), `graph-*` (Task 5), `capacity-*` (Task 6, added by the controller). Deliberate differing ids: Task 5 the `explain` probes; Task 7 the version probes; Task 8 the version probes, `cli.{empty,legacy,plan}.doctor.*` and `cli.{empty,legacy}.migrate.{plain,json}` (the baseline plan fixture is created by the tool's own `brain init`, `test/helpers/cli-fixture.ts:50`, so under 0.5.0 it is already format 2 and its `cli.plan.migrate.*` probes stay `up to date`).
