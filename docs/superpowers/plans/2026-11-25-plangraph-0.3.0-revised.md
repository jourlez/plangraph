# plangraph 0.3.0 revised plan (binding amendment)

This document amends `2026-11-24-zero-gaps-0.3.0.md` ("the old plan"). Where the two disagree, this one wins. Task text in the old plan still applies to every task marked "as old plan" below, with the amendments listed here. It was written after one audit pass of four independent reviewers (rename, privacy and history, Tasks 2 to 16, Tasks 17 to 24 and release) and the owner's decisions of 2026-11-25.

## 1. What changed and why

Goal: a plugin a team uses at work, with the security fixes and the correctness work of the old plan, one name (plangraph) everywhere, and graph v2 (typed nodes, derived relations, safe reassignment respecting blockers, links to superpowers plans and specs) as the next release. Work that only proves the playbooks were followed, without a user benefit, is deferred.

Exceptions, and only these: (1) the config key `brain_rules_version` stays until the graph plan's format-2 migration renames it (an old reader of a renamed key would silently default it and change staleness results); (2) `brainstorm*` (superpowers) never changes; (3) historical documents (`CHANGELOG.md` past entries, `docs/research/**`, `docs/superpowers/plans/**` and `specs/**` dated before 2026-11-25, `KNOWN_ISSUES` history) keep the old names and get a one-line banner; (4) the migration command and its test name the old names.

`plangraph migrate-names` (new command, explicit only; never run by a hook, `card` or any other command):
- Dry run by default, prints every change; `--apply` performs them. Refuses a dirty working tree for the repository part.
- User state: copies (never moves) `jira-sites.json`, `autopilot.json` from `~/.config/project-brain/` to `~/.config/plangraph/` with mode `0600`, refuses symlinks, never overwrites an existing new file, writes nothing else. The old folder stays; the command says it is safe to delete.
- Keychain: never read or written by the command (writing the secret would put it on a process argument list). It prints the one-line recipe to re-save the credential under `plangraph-jira`.
- Repository: renames `.brainrc` to `.plangraphrc` (content unchanged), `git mv`s the configured brain directory only when it is the default `.brain/` (a directory named by config, such as `docs/jira/plan-graph`, keeps its path), rewrites the `.gitattributes` merge line and the `.gitignore` lines, sets `merge.plangraph-jsonl.*` to the stable shim and unsets `merge.brain-jsonl.*`, and prints the steer-text change for `CLAUDE.md` and any `Bash(brain` permission rules it finds (it edits neither).
- Prints one line when it finds old state and nothing to do, so a second run is a no-op.

Steps (serial; one implementer, most capable available for the behavior commits):
1. Extend `scripts/repin.ts` with `--subst old=new` (whole-token, longest first, never inside `brainstorm`); test it on a fixture pin.
2. Behavior commits first: state and config paths, keychain service, driver name and shim name, `PLANGRAPH_*` reading (including the Python solver's own `BRAIN_DIR` reading), `.plangraphrc` and `.plangraph` defaults, `plangraph.sqlite`, `migrate-names`. Each with tests that can fail, including a real-git merge test with the new driver name and a Jira-binding test: an empty `~/.config/plangraph/` plus a populated old folder reads nothing (no fallback), and `migrate-names --apply` then makes the binding visible (the 0.1.3 regression, pinned the right way round).
3. Mechanical commits: launchers and file renames (`git mv`), `package.json`, `knip.json`, `lefthook.yml`, `hooks/hooks.json`, `.claude-plugin/plugin.json`, skills (frontmatter, directories, bodies), evals (by script, then `test/evals-schema.test.ts`), docs and README, command hint text, tests, goldens, fixtures.
4. `scripts/baseline.ts`: `normalizeOutput` applies the name map (old to new, whole token) to the pre-rename capture side only, so `differing: 0` is expected for every id except the deliberate ones (init, doctor, driver wiring, migrate-names, new probes). After capture, assert that the new tree's outputs contain no old name. Goldens are regenerated only by a script that applies the same map to the old goldens and requires byte equality with the new files except listed ids (`scripts/rename-check.ts`); never `UPDATE_GOLDEN=1` by hand.
5. `test/no-old-names.test.ts`: scans `git ls-files` for `brain` (word), `BRAIN_`, `project-brain` outside the exceptions above, excluding `brainstorm`. Fails on any stray.
6. Re-pin mutation pins with `repin.ts --subst`; `npm run mutate` still kills all pinned mutants; `test/equivalents.test.ts` green.
7. CHANGELOG `## [Unreleased]`: breaking rename, the migrate command, the manual keychain step, the merge-driver note ("every contributor updates before the repository's `.gitattributes` line changes: an unwired teammate text-merges the JSONL files").
Gate: the old plan's Gate with the deliberate ids above.

After release (not a task): the owner runs `plangraph migrate-names` dry run, then `--apply`, in each repository that uses the old names, with their explicit go for that repository.
