# 0.4.0 audit

Short record of what was verified for the 0.4.0 release and what was not.

## Verified

- Gate: `npm run bulletproof:check` (lint, typecheck, full test suite), `npm run knip`, `npm run mutate` (pins re-placed after the capacity and blockers moves).
- Behavior baseline: a capture of this tree compared with the capture of the renamed 0.3.0 tree (`node scripts/baseline.ts compare --only-common`) differs only in the deliberate probes (version, `explain` for `graph` and `repo`).
- Differential tests (`test/differential/`): rules, `whatif` and the solver agree with a brute-force oracle on small random plans. They run in the normal test groups (`scripts/ci-tests.ts`).
- Golden CLI output (`test/golden/mutation-kills/cli.json`) regenerated and reviewed: only the `repo` and `graph` entries were added.
- Baseline probes now include `graph-*` and `capacity-*` library calls.

## Known gaps

- Forward compatibility: a frozen 0.4.0 tree reading directories with `x-github.pr` nodes, `x-github/closes` links and an unknown xref `sys` (exit 0, v1 answers byte-identical) is not automated; check by hand before tagging.
- The xref merge limit on 0.3.0 and the start-up and size measurement against the frozen tree are hand checks, not recorded here.
- Hostile-input fuzz covers the commands registered in `test/hostile-fuzz.test.ts`; the new graph files are covered through those commands only.
- Task 4 tests not written (KNOWN_ISSUES.md must stay empty at a release version, so they are listed here): `blockers` output equal to the frozen 0.3.0 tree, `neighbors` depth 0, 21 and 50, a 25-hop `chain`, MCP ticket text, the cycle error, `person` and `sprint` with versions, the source built once per call, and `test/blockers-one-timing.test.ts`.
- Mixed-version teams: a 0.3.0 client cannot read node files. Upgrade every team member to 0.4.0 before anyone commits node files.
