# 0.5.0 audit

Short record of what was verified for the 0.5.0 release and what was not.

## Verified

- Gate, run once on the merged tree: `npm run bulletproof:check` (lint, typecheck, full test suite), `npm run knip`, `npm run mutate` (74 mutants, 74 killed, no re-pin needed). The code of Tasks 8 to 16 had never been typechecked or run before this gate; it found and fixed type errors, a template-literal syntax error, test fixtures that did not match the code, and the points below.
- Behavior baseline: a capture of this tree compared with the capture taken before 0.4.0 (`node scripts/baseline.ts compare --only-common`) differs only in the deliberate probes: `explain` (new commands), `sp-link` (usage names `--track`) and the MCP session (the `graph` tool, version). New probes: `graph-github-ticket-keys`, `graph-heuristic`, `graph-drift`.
- Read-only again: `graph KEY` is registered `writes: none`; the writer is the separate command `graph-materialize`, which the MCP adapter cannot reach.
- An index built by 0.4.0 (no `obs` table) opens as an older schema (stale, query-only, graph readers and index writers say STALE), in `src/db.ts` and the Python mirror in `bin/plangraph-solve`; `test/graph-views.test.ts` covers it.
- Golden CLI output and `test/golden/mutation-kills/*.json` regenerated and reviewed: the new command, the usage lines, `explain`, the MCP tool list and the `whatif` fixture (a `BLOCKED` warning on a ticket with an open item).

## Known gaps

- `verify` does not enforce `BLOCKED` or `SPRINT_CLOSED`: only `whatif` stops on them. A schedule that places a blocked ticket or uses a closed sprint passes `verify`.
- Task 12 (MCP): no `outputSchema`, no concise output modes, no `server/discover`, no `ttlMs` on resources.
- Task 14 (GitHub): the provider reads a saved file only; there is no CLI or network wiring that fetches pull requests, and the `touches` heuristic and `catalog-info.yaml` seed are library functions without a command that writes them.
- Task 15 (repair): the `whatif` CLI does not call the solver for the repair suggestion yet; `repairSpec` and `suggestionFromSchedule` build the call and read the result, and `bin/plangraph-solve --repair` runs it.
- Task 16 (solver measurement): the solver has no stage folding and no neighborhood flags; `lib/solver-measure.ts`, `lib/backtest.ts` and `lib/heuristic.ts` hold the pure helpers only.
- Forward compatibility of a frozen 0.4.0 tree reading 0.5.0 directories with cache files, and the mixed-version merge check, are hand checks, not automated here.
- `npm run knip` was run from a scratch install (the worktree shares `node_modules` without the knip binary); its only remaining lines are the scratch artifacts (`lefthook` and `knip` binaries not listed).
