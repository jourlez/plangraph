# plangraph 1.0 audit

Status: skeleton, written during Task 34. It lists what was checked and how, the gaps that are known and accepted for 1.0, and the risks that remain. Task 35 adds the clean-machine transcript and the independent review findings. Nothing here claims a token or accuracy benefit: the benchmark ruling is pending (`results pending`).

## 2. Known gaps (accepted for 1.0, stated in the README)

1. **`takeover` has no per-step rollback.** A failed step is recorded in `cache/takeover.json` and the later steps that do not need it still run; a re-run resumes. Files an earlier step wrote stay. The plan directory is under git, so `git restore` and `git clean` are the rollback, and the gap report says which step failed.
2. **The MCP server implements the legacy `initialize` flow and not `server/discover`.** A client that only speaks the newer discovery flow will not list its tools. Its default (`on`) is a placeholder until the benchmark ruling.
3. **The `PostToolUse` hook is not registered.** The plugin registers `SessionStart` and `UserPromptSubmit` only. Nothing updates the plan card after a tool call; the card refreshes at session start and through the git hooks the user enables.
4. **Unverified claims in `skills/docs-publish`.** The skill describes publishing a generated document to Confluence, Google Docs, Notion, Claude Docs or an Artifact. It was checked by skill-text and routing tests (`test/skills*.test.ts`), not by publishing to any of those services. Which of its statements about the connectors' behavior still hold was not re-verified for 1.0.
5. **Benchmark ruling pending.** The A/B harness exists and a small pilot was run; the full pass and the ruling on default injections have not happened (`docs/BENCHMARK.md`). The pilot showed equal accuracy and higher token use for the plugin arm. `results pending`.
6. **Live behavior of the 1.0 plugin.** The new hooks, skills and MCP tools were exercised through the CLI and test worlds, not in a live Claude Code session. Claude Code releases after 2.1.329 are untested.
7. **No command wraps `eraseNode`.** `docs/ERASURE.md` documents the library call and a manual procedure; no test checks the procedure end to end, and history rewriting is outside the tool.
8. **The tracker fetchers** (GitHub, Jira, Confluence) were tested against local doubles; real paging, rate limits and permissions were not exercised at scale.
9. **Windows is unsupported.** Nothing was run there.

## 3. Residual risks

- **Untrusted repository content.** `takeover` reads documents, commit messages, ADRs and tracker text from the repository and from trackers. Everything printed from them is fenced and capped; a fence bypass is the main prompt-injection risk, covered by tests but not provable. Skills must keep treating `<untrusted>` blocks as data.
- **Races on the file system.** Reads and writes check paths and symlinks, but an intermediate directory swapped between the check and the open is not detected in every case (README "Security model" lists the cases).
- **The index is unkeyed.** Its digest detects accidents, not a forger. The text files in git are the truth.
- **Hooks run as the user.** The plugin hooks and the optional git hooks run `plangraph` with the user's permissions; a git hook runs whatever `plangraph` is first on the `PATH`.
- **Supply chain.** The solver downloads pinned, hash-verified packages on its first run; the packages are not audited here. CI pins its actions by commit SHA but runs `npx @anthropic-ai/claude-code@2.1.329` without an integrity hash.
- **Git history.** Erasure of a person's data from history needs a rewrite by the owner (`docs/ERASURE.md`). The current history is not fit to publish (`docs/LAUNCH.md` items 10 and 12).
- **Format compatibility.** The stability policy has not yet been exercised by a real second release (`docs/STABILITY.md`).
- **Telemetry check is a source search.** A dependency or a Node feature that opens a socket outside the searched directories would not be seen; there are no runtime dependencies.
- **Single maintainer, no third-party review.** The independent review of Task 35 is not yet done.
