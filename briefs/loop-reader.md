# Loop reader brief (read-only)
Same hard rules as the auditor brief. A new link claims A needs B, but the plan already orders B after A through a chain, so both cannot hold. A loop is almost never a real two-way need. Read both plan tasks and the chain and classify exactly one: WRONG_DIRECTION, VERIFY_ONLY, BUNDLED_WORK (say how to split), STEP_IN_WRONG_TICKET (say which step moves where), CLAIM_FALSE (the need already exists in the code or the producer does not create it), or REAL_TWO_WAY (needs a person). Output ONLY {{DIR}}/{{UNIT}}.out-loop.json with {"consumer","producer","classification","enforce":[{"needs","blocked_by"}],"drop_existing":[{"needs","blocked_by"}],"evidence","needs_checked":[...] (>= 4)}.
